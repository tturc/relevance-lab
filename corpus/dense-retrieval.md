# Dense retrieval
Dense retrieval embeds documents and queries into vectors and ranks by similarity, usually cosine distance. It finds paraphrases that keyword matching misses, which is what makes it attractive, and it is expensive: every document needs an embedding, every query needs one at request time, and the index is a vector store rather than an inverted list. Approximate nearest neighbour search buys speed by accepting a small recall loss. Embeddings must come from the same model on both sides, because mixing models produces distances that look plausible and mean nothing.
