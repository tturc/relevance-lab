# Sharding search
A collection too large for one machine is split into shards, and a query goes to all of them. Scatter and gather means the slowest shard decides the latency of the whole query, so tail latency dominates: a node that is slow at the ninety ninth percentile becomes the ninety ninth percentile of the user experience. Mitigations are copies of each shard plus a hedge, sending the request to two replicas and taking the first answer, or tiering by popularity so the common queries never touch the cold shards. Aggregating scores across shards is only correct if each shard computes global statistics, or if the scores are normalised.
