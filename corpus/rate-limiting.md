# Rate limiting and fairness
A rate limit protects the service, but its shape decides who gets hurt. A global counter lets one client starve everyone else, so limits are usually per key: per address, per account, or per API token. Token bucket allows a burst up to the bucket size and then a steady refill rate, which suits interactive clients that go quiet and then spike. Leaky bucket smooths traffic to a constant rate. Whatever the algorithm, the limit has to be enforced before the expensive work rather than after, and the rejection has to be cheap, or the limiter becomes the bottleneck it was meant to prevent.
