# Inverted index
An inverted index maps each term to the list of documents containing it, with the count of occurrences. Reading it backwards from a forward index is the trick that makes search fast: instead of opening every document to see whether it mentions a word, you look up the word and get a candidate list immediately. Building one is a single pass over the collection: tokenise each document, count term frequencies, append the document to every posting list. The expensive part is not construction but maintenance, because adding a document means touching every term in it, and removing one means rewriting posting lists that can no longer shrink in place.
