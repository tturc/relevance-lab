# Hybrid retrieval
Keyword and vector retrieval fail in different directions, so combining them covers more ground than either alone. The usual approach is to run both, then merge the two ranked lists. Merging needs a common scale: raw BM25 scores and cosine similarities are not comparable, so either normalise both into a shared range or use rank fusion, which only looks at position in each list. Reciprocal rank fusion is the cheap default: score each document by the sum of one over its rank plus a constant. A reranker can sit on top of the fused list, but it costs a model call per candidate.
